The release that failed its health check never got a single request.

Shipyard starts the new build next to the live one, sends it nothing, and moves traffic only after the health route answers 200 inside the window you set.

Traffic moves at step four and not before.

Every release walks the same five steps. Only one of them can send a user to new code, and it sits behind the health gate.

  1. r-0412 / 41s

    Build

    The artifact is made once and reused for every instance.

  2. r-0412 / 6s

    Start beside

    New instances boot while the old release keeps serving.

  3. r-0412 / window 30s

    Health gate

    Your route must return 200. A 503 here ends the run.

  4. r-0412 / 2s

    Shift traffic

    The load balancer points at the new release.

  5. r-0411 / 60s

    Drain old

    The previous release finishes open requests, then stops.

The gate is four lines in a file you commit.

The window, the path and the number of old releases to keep live next to the code they protect, so a change to the gate goes through review like any other change.

[service]
name     = "api"

[health]
path     = "/healthz"
window   = "30s"
attempts = 6

[releases]
keep     = 3   # older ones are removed after drain
