Deployment tool for web apps

Deploy a web app from your terminal and roll it back from the same place

Shipyard builds your repo, starts the new version beside the old one and runs its health check. Traffic moves only when the check passes. When it fails, the old version keeps serving.

What a deploy does

  1. Build

    Runs your build command in a clean container with the runtime pinned in the repo.

  2. Image

    Packs the output into an image named after the commit, so each version stays addressable.

  3. Start

    Brings up the new instances next to the running ones. Nothing is stopped yet.

  4. Health check

    Requests the path set in shipyard.toml on every new instance and waits for a 200.

  5. Promote

    Shifts traffic to the new version and keeps the previous image warm for a rollback.

shipyard.toml

Build command and health path live in shipyard.toml at the repo root. The file is committed with your code, so a rollback restores the config that shipped with that version.

# shipyard.toml
[app]
name    = "web"
runtime = "node22"

[build]
command = "npm run build"

[health]
path    = "/healthz"
timeout = "30s"

[deploy.production]
regions   = ["fra1"]
instances = 2

Branches and previews

Each branch maps to a destination, and the CLI prints the URL when the deploy finishes.

main
Deploys to production when the health check passes.
feature/*
Gets its own preview URL on every push.
Closed pull request
Removes the preview and frees its instances.
shipyard rollback
Points production at the previous image without a rebuild.
